# MINING 实机纵向响应实验

本文描述 `mining_reactive` 的第五批实机实验。它与 `MINING_AI.md` 中早期 `lookahead` 合成模型是不同入口。

## 实现与参数

`forward_dynamics.enabled` 默认为 `false`。开启后必须显式提供 `zr_acceleration`、`normal_speed`、`normal_tau_seconds`。本次配置采用第三批安全连续片段拟合后冻结的参数：

```json
{
  "forward_dynamics": {
    "enabled": true,
    "zr_acceleration": 0.11552749024383441,
    "normal_speed": 0.25,
    "normal_tau_seconds": 0.7,
    "maximum_seed_age_seconds": 1.5
  }
}
```

速度单位为视口高度/秒，加速度单位为视口高度/秒²。按 ZR 的候选模型为 `dv/dt = a`；松开 ZR 的候选模型为 `dv/dt = (normal_speed - v) / tau`。每段用解析积分计算前进距离和段末速度，不把按下/松开 ZR 当作速度瞬间切换。横向模型、方向轴上限、完整机体和道路/石头硬约束保持原有配置。

监督器从本帧真实地标位移窗口取得带参考时刻的速度近似，通过已经提交的按键记录推进到捕获时刻，输出 `mining_forward_seed`。短期续推只允许距最后真实参考时刻不超过 1.5 秒；它明确标为估计，不是新增观测。碰撞、强化、非游戏状态和输入历史断裂会撤销种子；缺有效种子的帧回到原常速模型，并记录原因。

策略从捕获时刻开始，沿真实输入历史计算 `图像年龄 + 规划预算 + 提交等待 + 有效响应延迟` 的旧输入前缀。随后未来路线继续使用前缀末速度。一个候选搜索的 ZR/普通模式时序固定，因此同一层的横向候选共享纵向状态；混合模式在切换时刻精确拆段。星星跨模式比较仍要求完整路线到达同一深度，使用积分模型的到达时间，且不把已经由旧输入注定取得的星星计入新动作收益。

## 证据与适用范围

仓库记录 `artifacts/mining-A-campaign/vision-review/strict-vertical-segments.json` 保存了筛选条件、原始轨迹位置所对应的时刻和速度、训练/留出子段。第三批筛选得到 5 个 ZR、2 个普通模式安全连续子段；参数冻结后，在第四批独立的 10 个 ZR、3 个普通模式安全子段中，13 个子段的速度 RMSE 均小于原固定 0.5/0.25 模型。这是该记录和计算的结果，不等同于新策略已经获得更高实机分数。

实证主要覆盖约 0.25–0.49 高度/秒的安全短窗；普通模式留出仅 3 段。最高速度、长期 ZR 响应、撞停后的恢复以及强化响应尚未完成标定。超出观察速度范围的动态预测属于显式实验外推，当前不虚构终端速度，也不自动改回未必更可信的常速假设。

`forward_dynamics.active` 表示当前帧是否真正采用动态模型；`fallback_reason` 和 `seed_unavailable_reason` 解释未采用的原因。`seed_speed`、`seed_age_seconds`、`prefix_end_forward_speed` 可用于覆盖率和外推范围审计。`terminal_speed_measured: false` 明确最高速度尚未测定。路线和拾取诊断均为模型预测，实际碰撞、得分和等级仍以实机结果核验。

## 第六批准备：固定混合模式的松键时刻

第五批记录暴露了执行与规划之间的缺口：策略连续重算“再按 ZR 0.2 秒，然后松开”，可能每帧都把预计松键时刻后移。第一局 `158501–158557` 连续 11 帧选择混合模式，实际成功提交记录的连续 ZR 持续 1.002 秒，比首次计划的普通模式生效时刻晚约 0.813 秒。该段同时存在漏检石头，不能把后续碰撞单独归因于这项延期。

新增可选参数 `mixed_deadline_guard: true`，默认关闭。监督器保存首次混合计划的 host 请求截止时刻，后续只能保持或提前。核心按同一时钟重算剩余加速时间：`release_at + D + L - (capture_timestamp + prefix_seconds)`，其中 `D` 是提交预算、`L` 是有效响应延迟。剩余时间短于一个规划步时精确拆段，到期则按普通横向/纵向模型重新搜索。监督器有独立 lease 线程，到期归中；若策略计算跨过截止时刻，整条旧建议被中立状态替代，不保留按 ZR 模型求出的轴指令。

到期后的锁定只有在完成一次普通模型决策、实际成功提交历史中的普通模式已经按 `after + L` 进入当前捕获时刻、并且新策略找到完整的纯 ZR 安全路线时才能解除。另一个混合计划不能自行重启计时。`diagnostics.mixed_guard` 记录规划约束，trace 的 `execution_guard` 记录执行时否决原因；`policy_state` 保留原建议，`decision.state` 保留最终交给 lease 的状态。

## 第八批准备：圆环石形状与清路直线偏好

`circle_collision: {"enabled": true, "extra_radius_pixels": 0}` 只接受本帧真实亮环、唯一当前石头轨迹、规范 640×480 像素单位和准确捕获时刻组成的 `obstacle_shapes`。半径保留检测器已有的 3 像素外扩以及原检测框的横纵轴范围；机体尺寸、墙余量和位置不确定性均不缩小。缺少或有歧义的当前环证据立即回到 AABB。圆形碰撞仍是待实机检验的形状假说，不是已测碰撞箱。

前缀扫掠、未来路线、当前重叠面积、恢复动作和提前减速余量使用同一形状分派。`circle_guided_search: true` 只在普通模式默认路线不完整时，额外尝试一次对侧引导搜索；仍须完整路线通过所有当前形状和墙的硬约束。第六批保存的 `205935` 观测中，默认路线向右且不完整，这个候选找到先保持当前位置、从左侧通过的完整路线。录播反事实只验证模型路径，不能证明真实碰撞会消失。

用户要求清路尽量走直线时，配置 `straightness_clear_only: true`、`center_attraction_weight: 0.05`、`lateral_travel_weight: 0.04`。这减少搜索中的追中心收益，并计入分步累计绝对横移位移；可见前方出现星或石时恢复原代价。必要的转向仍由硬墙/石约束决定，输出端没有额外平滑。第七批 129 个固定观测的离线比较中，完整路线数量和预计星数保持 84、57，公共完整路径累计横移从 14.72 降为 12.76 个视口宽度；这些是多帧预测路径之和，不是实际行驶距离。

声明分类与置信度：代码行为、记录的样本数量和留出误差比较属于客观事实及计算得出，高（≥80%）；用这些方程预测下一轮短窗运动属于推测假设，低（20–50%）；长期/高速外推同属推测假设，低（20–50%），不能视为全域校准完成。
