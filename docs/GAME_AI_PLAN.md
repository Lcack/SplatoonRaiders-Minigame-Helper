# 四游戏实现顺序与状态模型

2026-10-30，根据用户补充调整，并同步本轮实现。三项均已接入参考视频的逐帧识别、跟踪和操作建议；当前交付范围是**参考录播分析与待校准的策略原型**，实机自动游玩效果仍待验证。使用方法和最终性能报告见 [视频分析说明](VIDEO_ANALYSIS.md)。以下软件设计属于工程推断；用户报告和 Wiki 的机制记载保留各自来源。

## 第一条实机闭环：JUGGLING

用户判断这是四项中相对容易完成的一项。优先用它完成“视频识别 → 多目标跟踪 → 双角色接球 → 手柄反馈”的第一条实机闭环。MINING 的现有规划器继续用于模型验证和路线优化，不把其进度当作完成其他游戏的前置条件。

接球的直接决策输入是每个目标的位置、碰撞范围、运动轨迹、所在半场及预计接触时间。**没有必要先把所有鱼种都识别得非常精细，才能开始接球**：可先统一检测可接目标，保持稳定 track_id，并按各条轨迹估计落点；只有鱼种影响轨迹、碰撞范围或遮挡关联时，再加入分类信息。这是工程选择，不是对鱼种无差异的规则断言。

已实现的快速路径包含颜色/形状目标候选、基于预测位置的全局匹配跟踪、左右半场分配和多目标到达时间比较。接球核心可使用可选的实测重力、横移速度和时延参数；参数缺失时采用局部轨迹近似，并将可达性保留为未知。输出两侧摇杆建议、目标 ID、预计接触位置、紧迫度及风险说明。滑步逻辑也已具备，但需要单独的校准配置和就绪读数，默认不凭空触发。

多个鱼体交叉、相似外观和遮挡仍会造成漏检或身份交换。跟踪器短暂保留漏检目标用于下一帧关联，不会把漏检预测冒充本帧看见的目标。仍需完整回合标注，分别评估漏检、换 ID、落点误差和错接；当前不能宣称识别了所有鱼种或已经可靠地自动接住所有目标。

识别速度应测量端到端延迟，而不只统计分类器 FPS。实时采集现在由独立分析线程读取最新帧，避免 GUI 绘制阻塞分析；分项记录识别、决策和必要时的控制发送耗时。最终统计及计时范围见视频分析报告，不能把纯策略耗时解释为采集卡到主机反馈的总延迟。鱼数量上限等 Wiki 中带推测措辞的数字不作为硬编码容量上限。[1]

## HOPPING：金色目标到强化消敌的收益链

用户补充的主要收益链为“踩金色锅盖鱼 → 掉卵 → 接卵 → 强化中接触空中/地面鲑鱼并击杀续时”。Wiki 同样描述金色空中目标掉卵及机器人、乌贼强化接触消敌，另外记载强化掉乌贼仍有惩罚。因此强化策略仍需保持接球和避免落地，不能仅追杀敌人。[1]

已将 `golden_enemy`、`egg_pickup`、已经生效的 `egg_buff` 和普通敌人分开处理。落卵与金色目标还使用参考片段模板辅助核对，未把普通红色鱼体直接认定为卵。当前策略能区分普通保球、紧急接球、争取金色目标、可返程接卵和强化保球/接触机会，输出模式、移动目标、预计接触与风险。

追卵需预留返回接球点的时间；未确认强化时仍按普通状态避敌，强化剩余有效时间未知时不主动远距离追撞地面鱼。B 键顶球建议需要显式允许和接触时窗，所附录播配置的时延与跳跃窗口属于待测启发式。识别到金色目标并准备顶球，不代表已证明下一次顶球能踩中它；完整弹跳、空中攻击与强化收割效果仍需实机验证。

## LANDING：布局库、逐图路线与反馈控制

本轮在可读的 Wiki 页面及日文攻略中**未能检索到完整 LANDING 地图册、稳定地图 ID 对应表或覆盖所有变体的路线库**。目前不能用“第几关”直接当作跨对局固定地图 ID。[1][2]

已有本地实况包含这一局第 1–10 关的可见布局。已抽取 27 张带时间索引的原始帧，并选取每关一张，登记在 `maps/landing/index.json`；这是**单局十个布局样本，不是全部地图**。本轮已由这些样本生成静态地形掩膜、布局匹配特征、几何路点与直立姿态参考，运行资料位于 `assets/landing_atlas`，可通过 `tools/build_landing_atlas.py` 重建来源派生资料。

现有分析链为：静态地形匹配确定本地布局 ID → 从当前位置搜索通道/路点 → 估计机器人朝向及角速度 → 输出 ZL、ZR、双喷射或松开喷射建议，并区分导航、着陆、制动和近身风险。姿态来自旋转模板比较，控制增益与角度阈值仍是实验性启发式。地图或姿态不明时保持等待，不用关卡序号替代布局识别。

静态几何路线尚未纳入完整的风场、敌人周期、惯性和双侧喷射响应；近身障碍检查也不能视为动态避障已完成。同局稀疏时刻的布局匹配检查不能代表跨视频地图准确率，姿态尚无逐帧角度真值，喷射建议尚未经过真实输入产生的轨迹验证。逐图策略仍需在上述通用控制骨架上逐张校准，而不是把当前几何路点称为已完成的通关脚本。

目前已有素材可以先启动这十个布局的整理；其他随机变体再通过后续视频扩充，不要求用户现在重录已有样本。

## 共同评估目标

以多局实机的分数分布、失败率、识别错误和端到端延迟评估效果；“最高分”暂作为优化方向，不能当作已证明的全局最优。固定录播仅能验证识别与建议，不会响应 AI 的反事实输入。报告中的 `phase_ready_frames` 和 `advice_frames` 只统计软件输出状态，不能解释为识别正确率或动作成功率。
