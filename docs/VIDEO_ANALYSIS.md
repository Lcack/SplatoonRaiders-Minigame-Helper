# 三项小游戏的视频分析原型

当前实现能从本地参考实况逐帧提取角色、目标和运动轨迹，给出摇杆/按键建议，导出中文标注视频与 JSONL。它没有完成实机闭环验证，不能用录像中的原玩家得分证明本策略有效。参考素材为已下载的同一条实况。[1]

## 运行与产物

项目目录下使用 conda base Python：

```powershell
python run.py gui --game juggling --video artifacts/reference_videos/utagaming-l3dMQV1sar8/reference.mp4
python run.py analyze-video artifacts/reference_videos/utagaming-l3dMQV1sar8/reference.mp4 --game hopping --start 382 --end 388 --annotated --output artifacts/my_hopping_analysis
python tools/analyze_reference.py
```

第一条打开回放界面。小游戏可改为 `hopping`、`landing`，已知参考文件自动跳转到对应章节。黄色十字表示建议站位/目标点，LANDING 的紫色线表示几何路线。界面可暂停、单帧和按秒定位。

第二条生成 `annotated.mp4`、若干 PNG、`trace.jsonl`、`summary.json`。标注视频保留原帧节奏，裁剪游戏区并在右侧显示中文建议，不带原声。`--stride 1` 为逐帧，`--stride 2` 为隔帧分析；隔帧可能影响轨迹与反应，不应拿来代替逐帧控制验证。

第三条顺序处理六段各 6 秒的片段，共 2,160 帧。输出位于 `artifacts/reference_analysis`，总报告为 `report.json`：

| 目录 | 源视频时间 | 目的 |
|---|---|---|
| hopping_egg | 382–388 秒 | 金色目标、落卵、强化外观转换；有标注视频 |
| juggling | 720–726 秒 | 两侧角色与多球建议；有标注视频 |
| landing | 983–989 秒 | 地图、姿态与喷射建议；有标注视频 |
| hopping_normal | 590–596 秒 | 另一段普通状态画面 |
| juggling_dense | 870–876 秒 | 另一段多球画面 |
| landing_wind | 1123–1129 秒 | 另一个含风场景的画面；未建立风力模型 |

## 已实现的分析

**JUGGLING**：把动态鲑鱼先统一当作需要接住的目标，跨帧使用速度预测和全局分配匹配身份。按预测接触位置分配左右半场，计算反弹、接触时间、紧迫度和可达性，分别输出双摇杆。只在明确配置并校准滑步参数、且有可用状态时建议 ZL/ZR。现阶段没有完整的鱼种分类器；普通局部匀速预测不覆盖所有鱼种行为。

**HOPPING**：优先维持乌贼接球，辅助识别普通敌人、金色锅盖、独立落卵和强化外观。卵与金色目标采用有来源帧的局部模板复核，避免仅凭红色/黄色直接认定。收益目标要经过可达、返程接球和局部碰撞检查；有可靠强化剩余时长时才考虑主动接触敌人。当前视频配置没有测得横移速度、重力和强化剩余时间，策略会限制这些动作。B 键顶球窗口是明确标注的启发式建议，尚未验证实机时机。

**LANDING**：捆绑这条视频单局出现的十个布局样本，按地形匹配而不是把关卡序号当成通用地图编号。建立膨胀障碍包络中的几何路线，以旋转模板估计朝向，并平滑角速度，给出左喷射、右喷射、双喷射或松开建议。地图未知、姿态不明或无路时保持中立。姿态模板步长为 10 度，未与人工角度真值对比；路线也未包含已测推力、风、燃料和动态敌人的完整模型。

地图的额外稀疏检查可用 `python tools/build_landing_atlas.py --check-samples` 重现。十帧用于构建图库，另十六帧是同局其他时刻，包含一个 CLEAR 遮挡拒识检查。结果仅评估这组地图匹配，不能推广为跨视频识别正确率或通关率。

## 实时链路与计时边界

控制回路是本地 OpenCV、数值跟踪和各游戏独立策略，没有逐帧调用联网大模型。采集线程只保留最新帧，分析线程独立于 GUI 绘制，不按旧帧 FIFO 排队；过载时跳帧。跨越较长空隙会重置轨迹，反弹时清除相反方向的速度历史。

每帧记录 `recognition_ms`、`decision_ms`、`analysis_ms`；离线另外记录 `decode_ms`。`analysis_ms` 为识别开始到策略结束，不含解码、绘制、视频编码、HDMI、采集卡、串口、主机接收和显示响应。实时模式还在实际提交控制的边界检查帧龄，释放权限后不会提交在途识别生成的晚到输入。

完整本机分项数据以生成的 `report.json` 为准，不能把分析耗时称为端到端响应时间。`phase_ready_frames` 与 `advice_frames` 只统计程序输出，不是识别准确率、操作正确率或得分。

## 当前限制

- 三份快速 profile 都是 `calibrated: false`、`advisory_only: true`，仅作视频分析与观察。实机配置需完成独立校准后才可启用控制，不能只修改一个标志就视为验证完成。
- ROI、颜色阈值、HUD 锚点和少量模板面向当前视频的画面尺寸与外观；新采集源、压缩、缩放和动画会影响识别。没有训练通用模型，也没有建立完整逐帧真值集。
- 角色接触、目标重叠时会漏检或身份不稳；多个相近乌贼候选会暂停建议，未匹配阶段和可识别的中央遮挡面板会停止建议。门槛仍可能漏过其他陌生画面。
- 快速配置的 `readouts` 为空，尚未读出倒计时、生命、得分或强化剩余秒数。SCORE 锚点仅辅助判断画面，显示的启发式置信分不代表统计正确率。
- 录像不能反馈本策略执行后的结果。当前不能据此证明能接住球、避免碰撞、落地成功或取得最高分。
