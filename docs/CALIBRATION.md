# 识别与回放配置

`profiles/mining.json` 仍是待校准的通用识别配置；HOPPING、JUGGLING、LANDING 三份配置已接入 `arcade_fast` 参考视频识别后端及各自策略。三份快速配置均为 `calibrated: false`、`advisory_only: true`，用于录播分析和操作建议。它们针对已下载实况的颜色、缩放和画面位置调参，不代表已完成采集卡或实机控制校准。

修改配置后重新启动观察，使配置重新载入。具体命令和最终计时范围见 [视频分析说明](VIDEO_ANALYSIS.md)。

## 坐标

`viewport` 是相对于完整采集帧的 `[x,y,w,h]`，范围 0..1。裁剪后统一缩放到 `reference_size`（默认 640×480）。所有检测器 ROI、数字槽和输出目标坐标都相对于这个缩放后的游戏区。y 向下增长，速度单位为“游戏区宽/高每秒”；手柄 y 的方向转换由 EasyCon 模块负责。

配置的基本字段包括 `version`、`game`、`viewport`、`reference_size`、`detectors`、`readouts`、`required`、`stable_frames`、`policy`、`calibrated`。`vision_backend: arcade_fast` 选择快速参考识别器；未选择时使用通用模板/HSV 识别器。

快速配置还读取 `score_anchor`，HOPPING 读取 `egg_template`、`golden_template`，LANDING 读取 `landing_atlas`。这些路径相对于 profile 所在目录。快速后端固定在 640×480 的规范化游戏区处理；参考实况的裁剪是原始 1920×1080 帧中 `[320,55,1280,960]` 的区域，再缩放到 640×480。其他截图布局、黑边或采集缩放必须重新检查，不能只沿用此 ROI。

实机校准完成前保持 `calibrated: false`。`advisory_only: true` 会独立阻止硬件启用；不能仅修改一个校准字段就把参考视频建议视为可靠的实机控制。实际启用还需实时采集、控制器连接与手动启用开关。

## 快速参考识别器

三项快速识别使用颜色/形状候选和目标跟踪；HOPPING 用少量真实片段模板辅助区分卵、金色目标，LANDING 加入布局匹配和旋转姿态模板。它们不是训练完成的通用视觉模型。相近颜色、多个目标相连、遮挡、动画变化及陌生画面可能误检；匹配得分和启发式 confidence 不能解释为真实正确率。

运行阶段目前依赖 HUD 锚点、角色候选、连续稳定帧和部分中央覆盖面板拒识。HUD 锚点只判断参考图案是否出现，**不会读出分数或剩余时间**。附带快速配置的 `readouts` 当前为空；倒计时、生命和分数等真实数值仍需另行标定。阶段判断也没有穷举所有菜单、暂停和结算画面。

预测跟踪器以位置、速度和尺寸进行一对一全局关联，短时漏检历史仅用于重新关联，不把未检测到的目标发布为“本帧可见”。跳转视频或时间间隔不连续时会重置轨迹；速度和姿态导数仍会受误检、反弹和量化影响。

## 检测器示例（结构示范，不是已校准参数）

```json
{
  "kind": "player",
  "method": "template",
  "path": "templates/player.png",
  "roi": [0, 0, 1, 1],
  "threshold": 0.9,
  "max_objects": 1
}
```

本节为通用 `Recognizer` 的检测器配置。模板路径相对于 profile 文件。先把原始画面按同一 viewport 裁剪并缩放到 reference_size，再裁剪角色，保证模板和待识别画面的尺度一致。可用 `tools/crop_template.py`；通用模板检测器当前不做旋转、透明掩膜或自动多尺度搜索。LANDING 的专用姿态模板另有旋转比较，不应与本节能力混淆。不同动画帧可能需要更多模板及跨模板去重，现阶段应避免把互相重叠的模板同时声明为同一角色。

阶段用 `phase:playing`、`phase:menu`、`phase:result` 等 kind。同一帧只允许一种阶段，且需连续 `stable_frames` 帧确认。`phase:playing` 应选运行阶段特有的图案；不要只依靠菜单和结算中也存在的固定装饰。

目标 kind 约定：`player`、`partner`、`ball`、`obstacle`、`wall`、`reward`、`egg_buff`、`egg_pickup`、`golden_enemy`、`enemy`、`goal`。`egg_buff` 表示**已生效的强化状态**，不能把尚未吃到的卵 `egg_pickup` 当作强化。快速识别器当前仍可能漏检或混淆，因此标注视频将卵、金色目标和强化外观显示为候选。

`hsv` 方法使用 OpenCV HSV 数值范围，字段为 `lower`、`upper`、`min_area`。它适用于合成回归测试和颜色较稳定的目标。真实画面的扫描线、色偏、动画和相似颜色会造成误检，需要用标注片段评估。

MINING 的 `corridor` 方法也使用 HSV 掩膜，另外提供 `scan_y`（道路多条采样线）、`min_width`（标准分辨率下的像素宽）。每条线上连续的道路片段输出为 corridor。默认基线仍要求扫描线的共同可行位置；新增 `lookahead` 规划器沿各层道路搜索弯曲路线，并要求扫描线覆盖玩家完整尺寸及规划前方。

可选 `fill_obstacles: true` 只恢复被已识别石头覆盖的内部道路缺口，避免强化石头被错误编码为墙；未知缺口和墙不填充，不扩展道路外边界。此功能取决于石头识别准确度，仍需要分割标注评估。日文 Wiki 报告道路背景随分数变色，需对不同颜色分别验证，见 `JAPANESE_SOURCES.md`。

## 倒计时和分数

通用识别器已实现固定数字槽的模板读取器。它没有自动为三项快速配置读取 HUD 数值；使用前须根据所选后端确认接入方式并标定数字模板。`readouts` 的每一项包含：

```json
{
  "name": "time_remaining",
  "slots": [[0.2, 0.01, 0.03, 0.05], [0.24, 0.01, 0.03, 0.05], [0.3, 0.01, 0.03, 0.05]],
  "decimals": 1,
  "threshold": 0.9,
  "templates": {"0": "digits/0.png", "1": "digits/1.png"}
}
```

这些槽位只是 JSON 格式示范，必须实测，不能照抄。实际应备齐 0..9 模板，slots 跳过小数点；若读到 4、0、0 且 decimals=1，输出 40.0。任一数字匹配不足、候选无法区分或画面为空时，不输出该指标。`name: score` 可读取右上分数。`time_remaining <= 0` 会使策略释放控制；读不到倒计时不会被当成 0。当前不推断计时增量，也未使用 OCR 模型。

## 四游戏策略配置

- MINING：通道、石头、加时物、强化状态分别识别。当前证据与规则统一在 `MINING_RULES.md`。新规划器还需运动速率、延迟、误差与强化有效区间；缺少测量时不启用，详见 `MINING_AI.md`。
- HOPPING：局部落点预测、保球、可返程接卵、金色目标准备和强化机会已接入。可选 `policy.gravity` 或 `metrics.ball_gravity_estimate` 提供实测重力，`policy.lateral_speed` 提供横向速率；缺少时不会把可达性当成已验证事实。B 建议需 `allow_jump: true` 与有效 `jump_window_seconds`，附带录播配置的窗口和时延为待测启发式。主动追撞还需可靠强化观测与 `buff_remaining_lower_bound_seconds`。
- JUGGLING：按预计接触半场而不只是当前位置分配目标，输出双摇杆建议；可选实测速率、重力和时延。ZL/ZR 滑步需策略与滑步配置均已校准、已启用且对应就绪读数成立，默认不触发。还需通过遮挡、交叉和多目标误关联的标注验证。
- LANDING：已生成十个同局布局的静态掩膜与几何路线，加入姿态/角速度估计和实验性喷射建议。地图或朝向不可靠时等待；路点、喷射增益、风与动态敌人响应仍待逐图实测，不能据此宣称已经自动通关。

## 公共视频的使用

2026-10-29 已通过浏览器观察公开视频，并将时间点与发现记录到 `RESEARCH.md`。2026-10-30 已按用户要求下载完整参考视频，存放在 `artifacts/reference_videos/utagaming-l3dMQV1sar8/reference.mp4`，参数及章节见 `LOCAL_VIDEO.md`。实机模板仍待校准。

已有本地视频时，`extract` 可生成原始帧及 `index.json`（视频路径、帧索引、时间），GUI 可暂停单步并保存截图。`analyze-video` 可输出逐帧 `trace.jsonl`、摘要及可选中文标注视频；其中识别、决策、解码分别计时，绘制/编码、HDMI/采集卡内部时延与串口不能算进纯分析耗时。

实时采集使用最新帧分析线程，避免按旧帧排队。输入提交边界会重新检查帧龄，过期或重复帧释放控制；这些措施不能替代硬件延迟测量。优先采样碰撞前后、加时前后、强化开始/结束、遮挡、游戏结束等片段。是否具备“稳定识别”应以人工标注比较为依据，不能用 ready/advice 帧数或合成演示通过率代替。

声明分类：配置字段和软件行为为客观事实，置信度高（≥80%）；校准顺序与算法适用性判断为逻辑推断，置信度中（50–80%）；示范坐标和物理近似为推测假设，置信度低（20–50%），不代表实测游戏参数。
